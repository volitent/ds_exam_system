# claude-progress.md
进度日志。每轮会话往里写，每轮新会话先读它。

## 写作规范
保持简短，节省下一轮上下文：
- 每条 session 控制在 ~15 行：做了什么 / 关键决策或取舍 / 仍存活的风险 
- 功能细节（参数、测试逐条、字段清单）归 feature_list.md，不在进度日志重复。
- 已解决的旧风险直接删，不保留历史噪声；长期不变的事实放文件顶部「架构速记」而非每轮重写。
- 旧 session 一旦 commit 且无存活风险，可合并压缩成一两行。

## 怎么用：
    - 每轮会话结束后更新会话记录

## 每个字段的意思：
- 当前已验证状态 — 项目当前进展的唯一真相
    - 仓库根目录 — 项目在哪
    - 标准验证路径 — 跑测试的命令
    - 当前最高优先级未完成功能 — 下一轮该做什么
    - 当前 blocker — 哪里卡住了
- 会话记录 — 每轮一条
    - 本轮目标 — 打算做什么
    - 已完成 — 实际做了什么
    - 运行过的验证 — 跑了什么测试
    - 已记录证据 — 留下了什么证明
    - 已知风险或未解决问题 — 哪里可能有问题
    - 下一步最佳动作 — 下一轮从哪开始

# feature_list.md
功能清单。机器可读的功能列表，每个功能有状态、验证步骤和证据。

# session-handoff.md
会话交接摘要。一轮会话结束时写，下一轮开始时读。让接手的人（或 agent）快速了解现状。

# DECISIONS.md
做出有取舍的设计/架构/选型决策时，追加一条到 DECISIONS.md，只记三件事：
- **什么决策**：标题用 `## YYYY-MM-DD: 一句话决策`
- **为什么**：`- 原因:` 一两行；有否决的替代方案时加 `- 否决方案:`（含否决理由）
- **约束**：`- 约束:` 该决策带来的硬性边界 / TTL / 阈值（如有）
不写详细设计文档；细节归 docs/ 与 feature_list.md。决策一旦记录不改写历史，被推翻时追加新条目说明。

# 书写风格：
简明扼要，每条记录不要过于冗长
